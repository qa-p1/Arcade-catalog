# Developer notes

- [`v1/`](v1/): the current work. The Arcade 1.0.0 plan: start with [v1/PLAN.md](v1/PLAN.md); decisions in
  [v1/README.md](v1/README.md), progress in [v1/PROGRESS.md](v1/PROGRESS.md).
- [`overhaul/`](overhaul/): the previous work (done; its STANDARD.md still applies unless v1 says otherwise). The Arcade overhaul specs, one per app, with the shared
  [standard](overhaul/STANDARD.md) and the audit evidence they are based on. Start with

- [`history/`](history/): past work, kept for reference. These plans, handoffs and test logs describe
  the ecosystem as it was when they were written; the apps' own `docs/STATUS.md` and Arcade Link's
  [SPEC.md](https://github.com/qa-p1/Arcade-Link/blob/main/SPEC.md) describe it as it is now.
  - [ARCADE_ECOSYSTEM_PLAN.md](history/ARCADE_ECOSYSTEM_PLAN.md): the first plan for the apps and Link.
  - [ARCADE_TOOLS_PLAN.md](history/ARCADE_TOOLS_PLAN.md): the plan for Arcade Tools.
  - [HANDOFF.md](history/HANDOFF.md): the handoff after that work.
  - [CLOUD_STRESS_TEST_PROMPT.md](history/CLOUD_STRESS_TEST_PROMPT.md) and
    [REAL_DESKTOP_TEST_LOG.md](history/REAL_DESKTOP_TEST_LOG.md): the stress-test brief and the real
    desktop test log.

How to build a new Arcade app is in Arcade Link's
[NEW_APP_SPEC.md](https://github.com/qa-p1/Arcade-Link/blob/main/NEW_APP_SPEC.md).
